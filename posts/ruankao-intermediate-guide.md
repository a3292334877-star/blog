很多人备考软考中级时，会走进同一个误区：把所有精力押在"数据结构与算法"上，考完发现下午大题的 UML 和设计模式根本没碰过，或者上午题的计算机组成因为没做过真题，每次算指令周期都出错。

软考中级（**软件设计师**）真正的难点不在于哪一模块特别艰深，而在于它同时考察**广度（上午 75 题）和深度（下午 6 题大题）**，需要两套完全不同的复习方法。把有限的复习时间精确投入到高频考点，比通读教材提分快得多。

## 一、先摸清题型结构：上下午各要过什么关

软件设计师考试分**基础知识（上午）**和**应用技术（下午）**两个科目，各 75 分满分，两科均需 ≥ 45 分才算通过。机考后两科连考，总时长 240 分钟，中途不休息（具体时长与场次以当次考试通知为准）。

| 科目 | 题型 | 题量 | 满分 | 合格线 | 核心特点 |
|---|---|---|---|---|---|
| **基础知识（上午）** | 单项选择题 | 75 题 | 75 分 | **45 分** | 覆盖面极广，单题 1 分，速度要快 |
| **应用技术（下午）** | 案例分析（4 必答 + 2 选 1） | 5 题 | 75 分 | **45 分** | 偏应用，机考作答，每题 15 分 |

### 下午题结构（近年标准格式）

| 题号 | 考查内容 | 作答要求 |
|---|---|---|
| 试题一 | 数据流图（DFD）/ 结构化分析 | **必答** |
| 试题二 | 数据库设计（ER 图 / SQL） | **必答** |
| 试题三 | UML 建模（类图、顺序图、状态图等） | **必答** |
| 试题四 | 算法与数据结构（C 代码填空） | **必答** |
| 试题五 | 面向对象设计（Java，含设计模式与代码填空） | 与试题六**二选一** |
| 试题六 | 面向对象设计（C++，含设计模式与代码填空） | 与试题五**二选一** |

> [!TIP]
> 下午必须答满 **5 题**：前四题全做，再在试题五、六中按自己熟悉的语言选一题。**算法题（试题四）是必答题**，不能放弃——哪怕写不出完整逻辑，也要把能看懂的填空和复杂度填上拿步骤分。选做只在五、六之间发生，别误以为可以跳过第四题。

## 二、上午题（75 分）：按模块命中率复习

上午 75 题覆盖约 **14 个知识域**，但历年真题数据显示，以下 7 个模块加起来占 **60%+** 的出题量：

| 模块 | 近年占比 | 重点考点 |
|---|---|---|
| 数据结构与算法 | ~15% | 时间复杂度、排序算法、树（BST / 堆 / AVL）、图（Dijkstra、Kruskal）、查找 |
| 计算机组成原理 | ~12% | 指令周期计算、Cache 命中率、流水线加速比、浮点数表示、DMA |
| 操作系统 | ~12% | 进程状态与调度、死锁四条件与银行家算法、页面置换（LRU/FIFO/OPT）、文件系统 |
| 软件工程 | ~12% | 瀑布 / 螺旋 / 敏捷模型、McCabe 圈复杂度、测试分类、CMM/CMMI 级别 |
| 数据库 | ~10% | 关系代数、范式（1NF/2NF/3NF/BCNF）、SQL 聚合、事务 ACID、索引 B+ 树 |
| 计算机网络 | ~8% | OSI 七层模型对应协议、子网掩码计算、TCP 三次握手、HTTP vs HTTPS |
| 程序语言与编译原理 | ~8% | 文法与正规式、LL(1) / LR 文法、符号表、中间代码 |

> [!NOTE]
> 其余约 20% 分散在知识产权法、信息安全、软件度量、项目管理等"送分题"模块。这类题目每年必出 8～12 题，直接按真题选项记答案即可，不必深究原理。

### 高频计算题快查

**Cache 命中率（h）→ 平均存取时间**

```
T_avg = h × T_cache + (1 - h) × T_mem
```

**流水线吞吐率（TP）**

```
# k 级流水，执行 n 条指令，每级时间 Δt
T_total = (k + n - 1) × Δt
TP = n / T_total
加速比 S = k × n / (k + n - 1)
```

**McCabe 圈复杂度（V(G)）**

```
V(G) = e - n + 2    # e: 边数, n: 节点数
V(G) = 判断节点数 + 1
```

**哈夫曼编码平均码长**

```
平均码长 = Σ (符号频率 × 对应码长)
权重路径长度 WPL = Σ (权值 × 叶节点深度)
```

## 三、核心模块精讲

### 1. 数据结构：三棵树必须烂熟

**二叉搜索树（BST）**：左子树所有值 < 根 < 右子树所有值。中序遍历得到升序序列。最坏情况（退化成链表）查找 O(n)，平衡时 O(log n)。

**堆（完全二叉树）**：大根堆父节点 ≥ 子节点。堆排序时间复杂度 **O(n log n)**，空间 O(1)，不稳定。建堆 O(n)，插入/删除堆顶均为 O(log n)。

**AVL 树**：任意节点左右子树高度差（平衡因子）≤ 1。失衡后通过旋转恢复——LL/RR 单旋，LR/RL 双旋。查找、插入、删除均保证 O(log n)。

**图算法速记**

| 算法 | 解决问题 | 时间复杂度 | 适用场景 |
|---|---|---|---|
| Dijkstra | 单源最短路 | O(V²) / O(E log V) | 无负权 |
| Bellman-Ford | 单源最短路 | O(VE) | 有负权，可检测负环 |
| Floyd | 全源最短路 | O(V³) | 节点数少 |
| Kruskal | 最小生成树 | O(E log E) | 稀疏图 |
| Prim | 最小生成树 | O(V²) | 稠密图 |
| 拓扑排序 | DAG 排序 / 检测环 | O(V+E) | 有向无环图 |

### 2. 操作系统：死锁和页面置换是高频大题来源

**死锁四个必要条件**（Coffman 条件）：

1. **互斥**：资源不能共享，同一时间只能被一个进程占用
2. **占有并等待**：进程持有资源的同时，在等待其他资源
3. **不可抢占**：已分配的资源不能被强制剥夺
4. **循环等待**：进程链，每个进程都在等待下一个进程占有的资源

**银行家算法**关键步骤：对每个进程判断 `Need = Max - Allocation`，当 `Need ≤ Available` 时分配并释放，更新 `Available`，直到所有进程完成（安全序列存在）。

**页面置换三大算法对比**（FIFO / LRU / OPT）：

```
访问序列：1 2 3 4 1 2 5 1 2 3 4 5，物理块数 = 3

FIFO：缺页 9 次
LRU：缺页 8 次
OPT：缺页 7 次（理论最优，实际无法实现）
```

> [!IMPORTANT]
> **Belady 异常**：FIFO 在增加物理块数时，缺页次数可能反而增加。LRU 和 OPT 不存在此异常。这是上午题常考的"坑"。

### 3. 软件工程：模型选择题套路固定

| 模型 | 记忆关键词 | 适用场景 |
|---|---|---|
| 瀑布模型 | 线性顺序、文档驱动 | 需求明确、变化少 |
| 原型模型 | 快速原型、尽早反馈 | 需求不清晰 |
| 螺旋模型 | **风险驱动**、迭代 | 大型复杂项目 |
| 增量模型 | 分批交付、可运行版本 | 急需部分功能 |
| 敏捷/Scrum | Sprint、自组织团队 | 需求频繁变化 |
| 形式化方法 | 数学规格、高可靠性 | 安全关键系统 |

**McCabe 圈复杂度**考法：给一段代码或流程图，要求计算 V(G) 并判断独立路径数。V(G) = 判断节点数 + 1，也等于流程图区域数（包括外侧无界区域）。

## 四、下午题（75 分）：五道作答大题逐个拆解

### 大题一：数据流图（DFD）

**核心概念**：外部实体（方框）→ 加工（圆角框/圆圈）→ 数据流（箭头）→ 数据存储（双横线）

**常见丢分点**：
- 忘记画**数据守恒**：流入加工的数据流之和应等于流出数据流之和（从信息角度）
- 把外部实体画成加工
- 数据流从数据存储直接流向外部实体（必须经过加工）

**答题模板**：

```
1. 识别外部实体（系统边界外的人/组织/系统）
2. 识别主要加工（动词短语，如"验证订单""生成报表"）
3. 识别数据存储（需要持久化的数据，如"用户表""订单表"）
4. 画出数据流方向，确保每个加工至少有一条输入和一条输出
5. 分层细化（0 层图 → 1 层图）
```

### 大题二：数据库设计（ER 图 + SQL）

**ER 图三要素**：实体（矩形）、属性（椭圆）、联系（菱形）+ 关联度（1:1 / 1:N / M:N）

**ER → 关系模式转换规则**：
- **1:1 联系**：可合并到任意一方，或单独建表
- **1:N 联系**：将"1"方的主键作为外键放到"N"方
- **M:N 联系**：必须单独建一张联系表，主键为两端实体主键的组合

**范式速记**（消除哪种依赖）：

| 范式 | 消除的依赖 | 记忆口诀 |
|---|---|---|
| 1NF | 属性原子性（无重复组） | 每格只一值 |
| 2NF | 部分函数依赖（非主属性完全依赖主键） | 非主全依主 |
| 3NF | 传递函数依赖（非主属性不依赖非主属性） | 非主不传递 |
| BCNF | 主属性也不能部分或传递依赖其他候选键 | 决定方必是键 |

### 大题三：UML 建模

**类图**（最高频，必须掌握）：

```
关联（Association）：—————
依赖（Dependency）：- - - >
聚合（Aggregation）：◇———（菱形在整体端，空心）
组合（Composition）：◆———（菱形在整体端，实心）
泛化/继承（Generalization）：———▷（空心三角在父类端）
实现（Realization）：- - -▷（空心三角，接口实现）
```

**顺序图**（Sequence Diagram）读法：从上到下是时间轴，箭头代表消息调用，激活框（细长矩形）表示对象处于活动状态。

**状态图**（State Diagram）：初始状态（实心圆）→ 状态（圆角矩形）→ 转移（带条件的箭头）→ 终止状态（双圆）

> [!TIP]
> 下午题 UML 大题通常给出部分类图，要求**补全缺失的类、属性、方法或关系**。解题关键：先读需求描述，找出名词（→ 类/属性），再找动词短语（→ 方法），最后判断类间关系（is-a → 继承，has-a → 聚合/组合）。

### 大题四：算法与数据结构（必答，C 代码填空）

**常考题型**：递归与分治、动态规划（0/1 背包、最长公共子序列、最长递增子序列）、贪心、图（DFS/BFS、最短路、最小生成树）、排序与查找、字符串处理。

**解题顺序**：

1. 先看函数签名、参数和注释，明确每个参数的语义与返回值
2. 顺着控制流读代码，定位空缺处"缺的是条件、下标还是递归调用"
3. 用题目给出的样例数据手工走一遍，验证填进去的代码
4. 最后补时间复杂度 / 空间复杂度（几乎每年都有一问）

**高频填空位置**：

| 位置 | 典型写法 |
|---|---|
| 循环边界 | `for (i = 0; i < n; i++)`、`while (low <= high)` |
| 递归出口 | `if (n == 0) return ...;` |
| 状态转移 | `dp[i] = max(dp[i-1], dp[i-2] + a[i]);` |
| 数组下标 | `a[i-1]`、`a[mid+1]`、`a[j] = a[j+1];` |
| 返回值 | `return count;`、`return dp[n];` |

> [!IMPORTANT]
> 试题四是必答题，不能放弃。即使写不出完整逻辑，也要把变量初始化、循环框架、边界条件和复杂度填上，这些步骤分加起来往往就有 5～8 分，直接决定 45 分线过不过。

**常见坑**：数组从 0 还是 1 开始、递归是否越界、`int` 是否会溢出（必要时 `long long`）、字符串结尾的 `\0`。

### 大题五 / 六：面向对象设计（Java 或 C++，二选一）

试题五和试题六考同一套面向对象设计能力，只是分别用 **Java** 和 **C++** 给出代码，**选一题作答即可**。题型通常是：给一段业务场景 + 类图 + 不完整代码，要求补全类名、属性、方法或设计模式相关代码，有时还要求说明某处用了什么模式、有什么好处。

> [!TIP]
> 语言选择只看一件事：**你平时真正写过哪门**。Java 模板代码少、不用管指针和头文件，零基础考生通常更稳；C++ 则要注意引用、指针与 `#include`。选定后另一题直接不答，不影响得分。

考试最常考的 8 个设计模式（多作为试题五 / 六的考点出现，不是独立大题）：

| 模式 | 类型 | 核心意图 | 识别关键词 |
|---|---|---|---|
| **工厂方法** | 创建 | 定义创建对象的接口，让子类决定实例化哪个类 | "具体产品由子类决定" |
| **抽象工厂** | 创建 | 创建相关或依赖对象的家族，不指定具体类 | "产品族" |
| **单例** | 创建 | 保证只有一个实例，并提供全局访问点 | "唯一实例" |
| **观察者** | 行为 | 对象间一对多依赖，一方变化自动通知所有依赖者 | "发布/订阅"、"事件监听" |
| **策略** | 行为 | 定义算法族，封装、互换，让算法独立于客户端变化 | "可切换的算法" |
| **装饰器** | 结构 | 动态地为对象添加职责，比继承更灵活 | "透明地增强功能" |
| **适配器** | 结构 | 将一个接口转换成另一个接口，使不兼容的类可协作 | "接口转换"、"旧接口复用" |
| **模板方法** | 行为 | 定义算法骨架，将某些步骤延迟到子类实现 | "算法骨架，子类填空" |

**答题套路（给代码填空题）**：

1. 读题时先找"哪些类是固定的，哪些是可扩展的" → 决定是**工厂**还是**策略**
2. 看类图中有没有 `<<interface>>` 或抽象类 → 决定**实现**还是**继承**
3. 找数量关系：1对多 → 通常是**观察者**；新增功能但不改原类 → **装饰器**

## 六、30 天可执行冲刺计划

**第 1～10 天：知识扫盲 + 高频模块速攻**
- 每天用 1.5 小时过一个高频模块（数据结构 / OS / 软件工程 / 数据库，各 2～3 天）
- 每天做 15 道对应模块的历年真题上午题，错题贴便利纸
- 把**计算题公式**整理到一张 A4 纸，贴在桌前，每天早上对着念一遍

**第 11～20 天：下午题专项突破**
- 每天精做 1 道下午大题，做完后对照标准答案逐句分析扣分点
- 重点攻 DFD（第 1 天 2 题）+ ER 图（2 天）+ UML 类图（2 天）+ **算法题（3 天，必答）** + 试题五/六 的面向对象与设计模式（2 天）
- 把 8 个高频设计模式的**类图默写**练习各 2 次，并挑 5 道真题完整敲一遍 Java / C++ 代码

**第 21～28 天：全真模拟 + 查漏补缺**
- 严格按考试节奏模拟 2～3 套近年完整真题（两科连考 240 分钟，中途不休息）
- 对照答案统计各模块得分率，低于 50% 的模块**专项回炉**
- 下午题对照自己机考敲出的答案，找出"表述不完整"的地方（如遗漏候选键、约束条件）

**第 29～30 天：心态调整 + 考点速览**
- 只翻计算公式速查表和设计模式类图，不做新题
- 确认准考证、考场路线与机考操作方式（部分考场提供草稿纸，可自带黑色签字笔）
- 上午题节奏：每题约 **1.5 分钟**，前 60 题尽量 90 分钟内完成，剩余时间回检

## 七、考场决策自测（点击展开解析）

<QuizPanel>
<template #question>1. 操作系统某进程的资源状态如下：系统共有资源 R 共 10 个，进程 P1 已分配 3 个、最大需求 9 个；P2 已分配 2 个、最大需求 7 个；P3 已分配 2 个、最大需求 4 个；剩余可用资源 3 个。当前状态是否安全？如安全，给出安全序列。</template>

**解答：安全，安全序列为 P3 → P2 → P1**

计算各进程还需资源（Need = Max - Allocation）：
- P1: Need = 9 - 3 = **6**，P2: Need = 7 - 2 = **5**，P3: Need = 4 - 2 = **2**

Available = 3，从 Need ≤ Available 开始：
1. P3: Need = 2 ≤ 3 ✓ → 执行后释放，Available = 3 + 2 = **5**
2. P1: Need = 6 > 5，P2: Need = 5 ≤ 5 ✓ → 先执行 P2，Available = 5 + 2 = **7**
3. P1: Need = 6 ≤ 7 ✓ → 执行后释放完毕

安全序列：**P3 → P2 → P1**。注意 P3 之后 P1 的 Need = 6 > Available = 5，不能先执行 P1；只有先跑 P2 把可用资源补到 7，P1 才能完成。
</QuizPanel>

**答案：B**

- A 描述的是**工厂方法模式**
- B 是**观察者模式**：一对多、状态变化、自动通知
- C 描述的是**装饰器模式**
- D 描述的是**模板方法模式**

观察者模式记忆口诀：**"主题（Subject）状态变，观察者（Observer）全知晓"**，常见实现场景：事件监听、MVC 中 Model 通知 View、消息订阅系统。

<template #question>3. 下午题数据流图中，以下哪种画法是错误的？<br>A. 数据流从外部实体流向加工<br>B. 数据流从加工流向数据存储<br>C. 数据流从数据存储直接流向外部实体（不经过任何加工）<br>D. 数据流从加工流向外部实体</template>

**答案：C**

DFD 的核心约束：**数据必须经过加工才能流动到外部实体或数据存储**。数据存储本身不会主动"产出"数据——它只能被加工读取或写入，然后由加工将结果输出给外部实体。

C 选项（数据存储 → 外部实体，无加工介入）违反了这一规则，是下午题最常见的绘图错误，也是阅卷扣分高频点。
